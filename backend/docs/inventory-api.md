# Inventory REST API

## Overview

The Inventory REST API provides database-backed operations for managing household inventory in PantryPlanner. It allows clients to create, retrieve, update, and delete inventory records through the Flask backend.

Inventory records are stored using SQLAlchemy and the existing `InventoryItem` model. The API is separate from the grocery list functionality, which currently uses its own implementation.

**Base URL:** `/api/inventory`

## Endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/inventory` | Retrieve all inventory items |
| GET | `/api/inventory/<item_id>` | Retrieve an inventory item by ID |
| POST | `/api/inventory` | Create a new inventory item |
| PATCH | `/api/inventory/<item_id>` | Update selected inventory fields |
| DELETE | `/api/inventory/<item_id>` | Delete an inventory item |

### GET — Retrieve All Inventory Items

Returns all inventory records ordered by `item_id`.

**Request**

```http
GET /api/inventory
```

**Response — 200 OK**

```json
{
  "items": [
    {
      "item_id": 1,
      "name": "Milk",
      "quantity": 2.0,
      "unit": "liters",
      "storage_location": "refrigerator",
      "expiration_date": "2026-12-01",
      "created_at": "2026-11-15T12:00:00",
      "updated_at": "2026-11-15T12:00:00"
    }
  ]
}
```

The timestamps above are illustrative; actual values are generated by the application.

If no inventory records exist, the API returns:

```json
{
  "items": []
}
```

### GET — Retrieve a Single Inventory Item

Returns the inventory record matching the specified ID.

**Request**

```http
GET /api/inventory/1
```

**Response — 200 OK**

The response contains an `item` object with the same fields shown in the collection response.

If the record does not exist, the API returns `404 Not Found`.

### POST — Create an Inventory Item

Creates a new inventory record and persists it to the configured database.

**Request**

```http
POST /api/inventory
Content-Type: application/json
```

```json
{
  "name": "Milk",
  "quantity": 2.0,
  "unit": "liters",
  "storage_location": "refrigerator",
  "expiration_date": "2026-12-01"
}
```

**Response — 201 Created**

Returns the newly created record inside an `item` object, including its database-generated ID and timestamps.

The `expiration_date` field is optional and defaults to `null` when omitted.

### PATCH — Update an Inventory Item

Updates selected fields of an existing inventory record. Only the fields supplied in the request are modified.

**Request**

```http
PATCH /api/inventory/1
Content-Type: application/json
```

```json
{
  "quantity": 1.5,
  "storage_location": "freezer"
}
```

**Response — 200 OK**

Returns the updated inventory record inside an `item` object.

Fields not included in the request retain their previous values.

To remove an existing expiration date, submit:

```json
{
  "expiration_date": null
}
```

Empty update objects and unsupported fields are rejected.

### DELETE — Remove an Inventory Item

Permanently deletes an inventory record from the database.

**Request**

```http
DELETE /api/inventory/1
```

**Response — 204 No Content**

A successful deletion returns no response body.

If the record does not exist, the API returns `404 Not Found`.

## Inventory Fields and Validation

| Field | Type | Requirements |
|---|---|---|
| `item_id` | Integer | Database-generated primary key; read-only |
| `name` | String | Required; nonblank; maximum 100 characters |
| `quantity` | Numeric | Required; positive; maximum two decimal places; less than 100,000,000 |
| `unit` | String | Required; nonblank; maximum 20 characters |
| `storage_location` | String | Required; nonblank; maximum 50 characters |
| `expiration_date` | Date or null | Optional; `YYYY-MM-DD` format |
| `created_at` | DateTime | Automatically generated; read-only |
| `updated_at` | DateTime | Automatically maintained; read-only |

All required fields must be provided when creating an inventory record.

PATCH requests may contain any supported writable field, but must contain at least one field.

Text values are trimmed before saving. Invalid quantities, malformed dates, unsupported fields, and missing required values are rejected.

Inventory quantities are stored using SQLAlchemy's `Numeric(10, 2)` type and converted to JSON numbers in API responses.

## Error Handling

The API uses structured JSON error responses.

**Example — 400 Bad Request**

```json
{
  "error": {
    "code": "bad_request",
    "message": "Missing required field: quantity"
  }
}
```

**Example — 404 Not Found**

```json
{
  "error": {
    "code": "not_found",
    "message": "Inventory item not found"
  }
}
```

| Status | Meaning |
|---|---|
| 200 | Successful retrieval or update |
| 201 | Inventory item created |
| 204 | Inventory item deleted |
| 400 | Invalid request data |
| 404 | Requested inventory item does not exist |
| 405 | HTTP method is not supported |
| 500 | Unexpected server or database error |

Database transactions are committed through SQLAlchemy. Failed database operations trigger a rollback and are passed to the application's centralized error handling.

## Database Configuration

The inventory API uses the existing SQLAlchemy configuration defined in `backend/config.py`.

The application supports:

- **SQLite:** Default local development database.
- **PostgreSQL:** Configurable through the `DATABASE_URL` environment variable.

Database schema changes are managed through Flask-Migrate and Alembic.

## Development and Testing

Run the full backend test suite from the project root:

```bash
python -m pytest backend -q
```

Run only the inventory API tests:

```bash
python -m pytest backend/tests/test_inventory_api.py -v
```

The inventory API tests use isolated temporary SQLite databases to verify request validation, database persistence, successful operations, and error handling.

The existing GitHub Actions workflow also runs the backend tests when a pull request targets `master`.

## Current Limitations

This implementation focuses on inventory CRUD functionality. The following features are outside its current scope:

- Frontend inventory dashboard integration
- User authentication and household ownership
- USDA food data integration
- Automatic transfer of checked grocery list items into inventory
- Expiration notifications

These features can be integrated with the inventory API in future development tasks.
